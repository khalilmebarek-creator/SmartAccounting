## 1. بيان سياسة الجودة (Quality Policy Statement)

تلتزم المنصة المحاسبية الذكية بتقديم برمجية محاسبية موثوقة، متوافقة مع النظام
الجبائي الجزائري، وآمنة، تلبّي احتياجات المؤسسات الصغيرة والمتوسطة، مع تحسين
مستمر للجودة من خلال اختبارات آلية، توثيق شامل، واستجابة منهجية لملاحظات
المستخدمين.

## 2. نطاق التطبيق (Scope)

- منتج: Smart Accounting Platform (تطبيق سطح مكتب، PyQt5، Windows 10/11)
- الأنشطة: التطوير، الاختبار، التغليف (Nuitka/Inno Setup)، التوثيق، النشر والتحديث
- ينطبق على كل الأقسام المشاركة في دورة حياة المنتج

## 4. إدارة المخاطر (Risk-Based Thinking — بند 6.1)

| الخطر | الأثر | الإجراء |
|-------|-------|---------|
| فشل CI بسبب تبعيات اختبار ناقصة | كسر الدليل الآلي للجودة | `requirements-dev.txt` في خطوة التثبيت بالـ CI |
| عدم تطابق الإصدارات بين الملفات | التباس لدى المراجعين/المستخدمين | فحص دوري: config.py ↔ pyproject.toml ↔ version.json ↔ index.html |
| غياب وسوم git للإصدارات | فقدان قابلية التتبع (traceability) | وسْم كل إصدار منشور فور رفعه |
| فقدان بيانات مستخدم عند الترقية | عدم رضا العميل | استثناء ملفات الحالة من المثبّت + اختبار ترقية آلي |

## 5. إدارة السجلات (Control of Records — بند 7.5)

- **سجل التنفيذ:** `PROJECT_MAP.md` — EXECUTION LOG (68 جلسة بتاريخ، هدف، نتيجة قابلة للتحقق)
- **سجل الإصدارات:** `CHANGELOG.md` + `docs/version.json` + GitHub Releases
- **منهجية التطوير:** `docs/DEVELOPMENT_METHODOLOGY.md` — دورة حياة الميزة + معايير القبول + الإجراءات التصحيحية (بند 8.1/8.3/10.2)
- **سجل الأخطاء:** جداول «أخطاء مكتشفة» في PROJECT_MAP — الجذر + الإصلاح + اختبار الانحدار
- **الاحتفاظ:** المستندات متعقّبة في git — محفوظة وقابلة للاسترجاع لأي إصدار

## 6. التحسين المستمر (Continuous Improvement — بند 10)

1. كل ملاحظة مستخدم → جلسة معالجة موثقة (انظر جلسات 2026-08-02/03)
2. كل خطأ مكتشف في اختبارات التكامل → إصلاح + اختبار انحدار
3. مراجعة دورية: توزيع مقاييس جودة أعلاه + فحص الاتساق (أرقام الشاشات/الاختبارات/الإصدارات)

## الجزء الأول: منهجية النماذج (لماذا استخدمت هذه الطريقة؟)

### 1. تحليل DuPont (العائد على حقوق الملكية)

**الصيغة (مطابقة لـ `modules/analysis.py`):**

```
هامش الربح الصافي  = صافي الدخل / الإيرادات × 100
دوران الأصول       = الإيرادات / إجمالي الأصول
الرافعة المالية    = إجمالي الأصول / حقوق الملكية
ROE                = (هامش الربح / 100) × دوران الأصول × الرافعة المالية × 100
```

**لماذا هذا التحلل؟** DuPont **بنيوياً** معادلة تفكيك، مو "صيغة مبسطة" — الهدف أن يتحلل ROE إلى ثلاثة مصادر مستقلة للربحية:
1. **الهامش** → هل تكسب من كل دينار مبيعات؟ (كفاءة تسعير/تكلفة)
2. **الدوران** → هل تستخدم أصولك بكفاءة لتوليد مبيعات؟
3. **الرافعة** → هل تستفيد من الديون لرفع العائد؟

**الرد الجاهز عند سؤال "لماذا؟":** *"لأن ROE وحده مضلّل: شركة قد ترفع ROE بالديون الزائدة (رافعة عالية) رغم ضعف العمليات. التفكيك يكشف المصدر الحقيقي للربحية، وهذا ما يعرضه رسم الشلال: الأثر الصافي للهامش ثم الدوران ثم الرافعة."*

**حدود النموذج (قُلْها قبل أن يسألك):** عندما تكون حقوق الملكية سالبة أو صافي الدخل سالباً، يصبح ROE غير ذي معنى — والكود يعالج القسمة على صفر (`_safe_div`).

### 2. Z-Score (نموذج Altman للتنبؤ بالإفلاس)

**الصيغة (مطابقة لـ `modules/calculations.py`):**

```
Z = 1.2·X1 + 1.4·X2 + 3.3·X3 + 0.6·X4 + 1.0·X5

X1 = رأس المال العامل / إجمالي الأصول        (سيولة)
X2 = الأرباح المحتجزة / إجمالي الأصول        (عمر الشركة/تراكم الأرباح)
X3 = EBIT / إجمالي الأصول                    (ربحية التشغيل)
X4 = القيمة السوقية / القيمة الدفترية للخصوم (ملاءة)
X5 = المبيعات / إجمالي الأصول                (كفاءة الدوران)
```

**التصنيف:** Z > 2.99 آمن / 1.81–2.99 منطقة رمادية / < 1.81 خطر.

**الرد الجاهز:** *"نموذج Altman (1968) هو المرجع الأكاديمي الأشهر لتقييم مخاطر الإفلاس، مبني على تحليل تمييزي لـ 66 شركة. استخدمته لأنه شفاف وقابل للتفسير مقابل نماذج ML صندوق أسود."*

**حدود مهمة (كن صادقاً):** Altman صُمم أصلاً **للشركات الصناعية المدرجة في البورصة الأمريكية** — تطبيقه على شركات جزائرية غير مدرجة فيه تقريب، لأننا نستخدم القيمة الدفترية للخصوم بدل القيمة السوقية (غياب بورصة نشطة). اعرضه كـ **مؤشر إنذار مبكر** مو حكم قطعي.

### 3. التنبؤ المالي (التحليلات التنبؤية — ليست تعلم آلي)

**الطرق الثلاث (مطابقة لـ `modules/ai_insights.py`):**

| الطريقة | الفكرة | متى تناسب |
|---------|--------|-----------|
| الانحدار الخطي | تركيب خط اتجاه | بيانات بلا موسمية |
| المتوسط المتحرك | متوسط آخر n فترة | تسوية التقلبات |
| التجانس الأسي | وزن تنازلي للفترات الأقدم | بيانات حديثة أهم |

**فترات الثقة 95%** حول التنبؤ (متوسط ± 1.96 انحراف).

**رد جاهز للحرج الأكبر (سؤال "هل هذا تعلم آلي؟"):**
*"لا — هذه تحليلات إحصائية كلاسيكية، وليس تعلّم آلي. وهذا قرار تصميمي مقصود، مو نقص: بدون sklearn يعني أسرع في التشغيل وأخف في الحجم وأشفّ في التفسير (أستطيع شرح كل رقم) مقارنة بصندوق أسود يحتاج مئات آلاف السجلات التاريخية — وهي غير متوفرة لشركة صغيرة جزائرية."*

> **نصيحة:** في الواجهة والوثائق، استخدم مصطلح **"تحليلات تنبؤية إحصائية"** بدل "الذكاء الاصطناعي/تعلم الآلي" عندما يكون المقصود التنبؤ وكشف الشذوذ. "الذكاء الاصطناعي" كعنوان مظلة مقبول، لكن لا تدّعِ ML.

---

### 4. كشف الشذوذ

- **z-score للأرباح**: قيمة تبعد >3 انحرافات عن المتوسط = شذوذ (قاعدة 68-95-99.7).
- **IQR للمعاملات**: أي معاملة خارج `[Q1 − 1.5×IQR, Q3 + 1.5×IQR]` = شاذة.

**رد جاهز:** *"هذه طرق إحصائية غير مُعلّمة (Unsupervised) قياسية في كشف القيم المتطرفة، وهي الأفضل لبيانات مالية صغيرة الحجم."*

---

### 5. درجة الصحة المالية (0–100)

**الوزن (مطابق لـ `modules/ai_platform.py`):** ربحية 30 + سيولة 20 + مديونية 15 + كفاءة 15 + نمو 10 + استقرار 10 = **100**.

**رد جاهز:** *"الدرجة مؤشر تجميعي موزون نتيجته سهلة القراءة لصاحب القرار غير المتخصص، مع تفكيك تام لكل محور كي لا تتحول لرقم غامض."*

### 6. النظام الجبائي الجزائري

**المصدر:** نشرة DGI الرسمية "النظام الجبائي الجزائري 2026".

**رد جاهز:** *"الجباية الجزائرية من أعقد الأنظمة محلياً، فجعلتها قابلة للتحديث السنوي عبر ملفات JSON (`config_years/`) بدل ترميز القيم، حتى يواكب النظام النشرات الجديدة دون إعادة بناء."*

## الجزء الثاني: 30 سؤالاً متوقعاً مع أجوبة

### أ. أسئلة عامة (المشكلة والحل)

1. **ما المشكلة التي يحلها مشروعك؟** — الشركات الصغيرة والمتوسطة الجزائرية (95% من النسيج الاقتصادي) تفتقر لأداة محلية موحّدة تجمع المحاسبة + الجباية الجزائرية + التحليل بالعربية، وتهرب لأدوات أجنبية لا تفهم IBS/TVA/IRG الجزائرية.

2. **لماذا الجزائر تحديداً؟** — النظام الجبائي الجزائري فريد (IFU، VF، شرائح IRG خاصة، تقويم استحقاقات DGI) ولا توجد أدوات عربية RTL مخصصة له.

3. **من المستخدم المستهدف؟** — صاحب مؤسسة صغيرة/متوسطة ومحاسبه، مع 4 أدوار (مدير/محاسب/مراجع/قارئ).

4. **ما البدائل الموجودة؟ ولماذا مشروعك أفضل؟** — برامج أجنبية (QuickBooks/Sage) بلا جباية جزائرية وبلا عربية، أو Excel يدوي معرّض للخطأ. مشروعك: محلي + عربي + آلي + قابل للتصدير.

5. **ما أهم ميزة تميزك؟** — الجمع بين المحاسبة الكاملة والجباية الجزائرية المحدّثة سنوياً في واجهة واحدة بالعربية مع تحليلات تنبؤية.

### ب. أسئلة تقنية (البنية والبيانات)

6. **ما البنية المعمارية؟** — سطح مكتب PyQt6 + SQLite (عبر SQLAlchemy Core) + وحدات Python مفصولة (MVC بطبقة modules/ منطق خالص + ui/views واجهة).

7. **لماذا PyQt6 وليس ويب؟** — تطبيق سطح مكتب يعمل دون إنترنت (مطلب أساسي للشركات الجزائرية)، مع موقع docs/ للتحميل والتحديث.

8. **لماذا SQLite وليس خادم؟** — بيانات مالية حساسة محلياً، حجم بيانات صغير، لا حاجة لخادم؛ SQLite مع WAL واتصال مجمّع يعطي أداءً كافياً.

9. **كيف تحمي البيانات؟** — كلمات مرور PBKDF2 + ملح لكل مستخدم، 2FA، تشفير AES-256-GCM للمزامنة السحابية، ترميز Argon2id للسناب شوت.

10. **كيف تمنع حقن SQL؟** — كل الاستعلامات معاملات (parameterized) عبر SQLAlchemy Core / `?`، لا concatenation.

11. **لماذا SQLAlchemy Core لا ORM؟** — Core أنسب لعمليات قراءة/كتابة مالية بسيطة وخفيف، ويتيح تحكماً أدق في الاستعلامات.

12. **كيف تعمل المزامنة السحابية؟** — تصدير snapshot بchecksum → تشفير اختياري AES-GCM → رفع لوجهة (Drive/Dropbox/OneDrive) → استرجاع بتحقق من التكامل.

13. **كيف يتحدّث التطبيق مع تطبيق الجوال؟** — الجوال يقرأ ملفات snapshot (حتى المشفرة SACF1) المصدرة من سطح المكتب، بفك تشفير متطابق في Dart (اختبارات parity).

14. **ما آلية التحديث؟** — فحص `version.json` من GitHub Pages + تحميل المثبّت + استبدال آمن (Excludes تحفظ بيانات المستخدم).

### ج. أسئلة منهجية (لماذا هذه الصيغة/الطريقة)

15. **لماذا DuPont تحديداً لتحليل ROE؟** — (انظر الجزء الأول، قسم 1).

16. **ما حدود Z-Score عندك؟** — (قسم 2: تطبيقه على شركة جزائرية غير مدرجة تقريب، القيمة السوقية مستبدلة بالدفترية).

17. **لماذا الانحدار الخطي للتنبؤ لا شبكة عصبية؟** — (قسم 3: شفافية + بيانات محدودة + بدون تبعيات).

18. **كيف اخترت أوزان درجة الصحة (30/20/15/...)؟** — أوزان معايرة حسب الأهمية النسبية في التحليل المالي (الربحية أهم من النمو)، وموثقة وقابلة للتعديل.

19. **من أين أتت المعايير القطاعية المرجعية؟** — قيم مرجعية لكل قطاع (7 قطاعات) مبنية على نسب مقبولة في الممارسة، مقسمة لمثالي/متوسط/حرج.

20. **كيف تحقق أن حساباتك الضريبية صحيحة؟** — مقابل نشرة DGI الرسمية 2026 + اختبارات وحدة بمدخلات معروفة النواتج.

### د. أسئلة الجودة والاختبار

21. **كم اختباراً؟ وتغطية؟** — 2106 اختباراً، تغطية وحدات modules بنسبة 100% (قياس `coverage`).

22. **كيف تضمن عدم كسر الميزات عند التعديل؟** — TDD: اكتب الاختبار، تأكد فشله، ثم اجعله ينجح + تشغيل المجموعة كاملة قبل كل رفع.

23. **ما الذي كشفته اختباراتك؟** — أمثلة حقيقية: بغّ ترميز `config.py` (cp1252/soft-hyphen)، بغّ `ias_reports` (استدعاء `_safe()` على dict)، بغّ placeholders (الشاشات فوق 37 لا تظهر). كلها وُثّقت وأُصلحت.

24. **هل يوجد CI؟** — نعم، GitHub Actions (Ubuntu + xvfb) تشغّل الاختبارات تلقائياً عند الدفع.

25. **كيف تقيس الأداء؟** — اختبارات أداء للإقلاع (≤3 ثوان) وتحميل المشاهد والذاكرة.

### هـ. أسئلة تحدّي (الأسئلة الصعبة)

26. **ما أضعف نقطة في مشروعك؟** — *"صادقاً: بعض الحسابات تستخدم معادلات مرجعية قياسية أكثر من كونها معايرة على بيانات جزائرية حقيقية، لأن البيانات المالية المجمّعة للشركات الجزائرية غير متاحة علناً. المعايرة على بيانات حقيقية هي الخطوة التالية."*
